# Работа в команде

Проект разделён на три части: база (`database.py`), правила бронирования
(`airline.py`) и меню (`main.py`). Распределите их между участниками и запишите
в отчёте фактический вклад каждого. На защите каждый должен понимать весь
путь от ввода в меню до SQL-запроса.

Код изначально подготовлен с помощью AI; учитывайте правила курса об указании
использованных инструментов.

## Изменения

Работайте в отдельных ветках. Например:

```bash
git switch main
git pull --ff-only
git switch -c feature/search
```

Сохраняйте стандартную библиотеку Python и простую структуру проекта.
Комментарии нужны только для неочевидных решений. После изменения запустите
тесты и проверьте затронутый сценарий через меню:

```bash
python3 -m unittest discover -s tests -v
python3 main.py --database demo.db
```

Коммитьте нужные файлы, затем открывайте pull request:

```bash
git add airline.py
git commit -m "Fix passenger search"
git push -u origin feature/search
```

## База и отчёт

У каждого участника своя локальная база. Изменения данных через Git
не передаются. Для чистой репетиции используйте новый путь `--database`.
Если нужна копия существующей базы, закройте приложение перед копированием.

Один участник собирает итоговый архив. Он проверяет количество записей
и экспортирует отчёт из той же базы, которая попадёт в архив.
