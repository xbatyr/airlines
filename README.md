# Airline Reservation System

Консольная система бронирования авиабилетов на Python и SQLite.
Хранит рейсы, пассажиров и билеты, поддерживает поиск, изменение данных,
отмену бронирования и экспорт отчёта. Интерфейс программы на английском.

## Запуск

Нужен Python 3.10 или новее. Сторонних библиотек нет.

```bash
python3 main.py
```

На Windows можно использовать `python main.py`.
При первом запуске пустая база заполняется 20 рейсами, 50 пассажирами
и 40 билетами. Данные учебные. Повторный запуск сохраняет изменения;
если хотя бы в одной таблице есть записи, генерация пропускается.

По умолчанию `project.db` и отчёт `results.txt` находятся рядом с `main.py`,
независимо от папки запуска. Отчёт создаётся через пункт **7**.

Для репетиции с отдельными данными:

```bash
python3 main.py --database demo.db
```

В этом случае отчёт сохранится в `demo.results.txt`. Повторный запуск с тем же
путём откроет ту же базу. Можно указать другое место для отчёта:

```bash
python3 main.py --database demo.db --report demo-report.txt
```

## Меню

```text
1. Add information
2. Display records
3. Search
4. Update
5. Delete or cancel
6. Show statistics
7. Export results
0. Exit
```

Добавление, просмотр, изменение и удаление доступны для всех трёх типов записей.
При изменении нужно ввести все поля заново. Удаление требует ввода `yes`.
Поиск работает по имени или ID пассажира и по части названия города назначения,
без учёта регистра, в том числе для кириллицы. Если совпадений нет, программа
пишет `No records found.`

## Данные и правила

| Таблица | Поля |
| --- | --- |
| `flights` | `id`, `number`, `origin`, `destination`, `departure`, `seats`, `price` |
| `passengers` | `id`, `name`, `email` |
| `tickets` | `id`, `flight_id`, `passenger_id`, `seat`, `price` |

Билет связан с рейсом и пассажиром через внешние ключи. Номер рейса и email
уникальны. На одном рейсе нельзя дважды занять место или забронировать два
билета одному пассажиру. Перед выбором места выводятся диапазон и занятые места.
При изменении билета список включает и его текущее место — его можно оставить.

- Номер рейса: две латинские буквы и 3–4 цифры, например `KC123`.
- Дата: `YYYY-MM-DD HH:MM`, с проверкой календаря.
- Города отправления и назначения должны отличаться.
- Вместимость, место, ID и цена — положительные целые числа.
- Цена хранится в целых тенге.
- Нельзя уменьшить вместимость ниже максимального занятого места.
- Перед удалением рейса или пассажира нужно отменить связанные билеты.
- Изменение цены рейса не меняет цену ранее купленного билета.
- При переносе билета на другой рейс используется цена нового рейса.

Выручка — сумма цен **активных** билетов. Отмена удаляет билет и уменьшает эту
сумму. Общая заполняемость — число билетов / сумма мест всех рейсов × 100%.
Для пустой базы результат равен 0. В отчёте есть и заполняемость каждого рейса.

Это локальный учебный проект: оплаты, возвратов и истории отмен нет.
Дата вылета проверяется на корректность, но прошлые даты разрешены;
статистика включает все сохранённые рейсы. Часовые пояса не рассчитываются.

Из дополнительных модулей используются `re` для проверки форматов и `random`
для начальных данных. `random.Random(26)` делает набор воспроизводимым.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Тесты используют временные папки и не меняют основную базу.
GitHub Actions запускает их при push и pull request.

## Перед сдачей

Базы и выгрузки не хранятся в Git. В итоговый архив нужно отдельно положить
`project.db`, свежий `results.txt`, три модуля Python, отчёт PDF и презентацию.
Проверьте минимум 20 рейсов, 50 пассажиров и 40 билетов в сдаваемой базе.
Оставшиеся пункты перечислены в [чек-листе](docs/requirements.md).
